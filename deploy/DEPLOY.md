# Deploying to AWS

This runbook deploys the service on AWS in a minimal but real way. The API runs
as a container on AWS App Runner. The database runs on Amazon RDS for PostgreSQL
with the pgvector extension. Answers are generated by Amazon Bedrock, which you
already use locally.

Nothing in this repository provisions cloud resources on its own. You run the
commands below yourself, so you stay in control of what gets created and what it
costs.

## Read this first: cost

Creating these resources costs money for as long as they exist. Rough figures at
current on demand prices in us-east-1, for a low traffic demo:

- RDS `db.t4g.micro` PostgreSQL, single instance, 20 GB storage: about 12 to 16
  USD per month. This runs continuously and is the main cost.
- App Runner: billed for provisioned container memory plus requests. A single
  small instance that is allowed to scale to zero active instances costs a few
  USD per month at low traffic.
- Bedrock: billed per token. The whole evaluation suite is a few US cents. Normal
  question traffic is fractions of a cent per question.
- ECR image storage and data transfer: cents per month.

The total for a demo left running is roughly 15 to 25 USD per month, almost all
of it RDS. If you only want to show the deploy working, stand it up, record it,
and tear it down the same day. The teardown section removes every billable
resource.

Set your region and a name prefix once, and reuse them in the commands below.

```bash
export AWS_REGION=us-east-1
export PREFIX=ika
export ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
```

## Prerequisites

- An AWS account and the AWS CLI, signed in with permission to create ECR, RDS,
  IAM, and App Runner resources.
- Docker, to build the image.
- Bedrock model access enabled in this region for the Titan embedding model and
  the Claude model you plan to use. Confirm with `py -3.11 -m scripts.check_bedrock`
  pointed at the same region.

## Step 1: build and push the image to ECR

```bash
aws ecr create-repository --repository-name $PREFIX-api --region $AWS_REGION

aws ecr get-login-password --region $AWS_REGION \
  | docker login --username AWS --password-stdin \
    $ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com

docker build -t $PREFIX-api .
docker tag $PREFIX-api:latest \
  $ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PREFIX-api:latest
docker push $ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PREFIX-api:latest
```

## Step 2: create the database

Create a small PostgreSQL instance. Pick a strong master password and keep it
somewhere safe. This example makes the instance publicly reachable so you can
apply the schema and ingest from your laptop. You will lock it down to your own
IP address, and you will make it private again in the teardown.

```bash
aws rds create-db-instance \
  --db-instance-identifier $PREFIX-db \
  --engine postgres \
  --engine-version 16.4 \
  --db-instance-class db.t4g.micro \
  --allocated-storage 20 \
  --storage-type gp3 \
  --master-username ika \
  --master-user-password 'REPLACE_WITH_A_STRONG_PASSWORD' \
  --db-name ika \
  --publicly-accessible \
  --backup-retention-period 0 \
  --region $AWS_REGION
```

Wait for it to become available, then read its endpoint address:

```bash
aws rds wait db-instance-available --db-instance-identifier $PREFIX-db --region $AWS_REGION
export DB_HOST=$(aws rds describe-db-instances --db-instance-identifier $PREFIX-db \
  --query 'DBInstances[0].Endpoint.Address' --output text --region $AWS_REGION)
echo "DB host: $DB_HOST"
```

Allow your own IP address to reach the database on port 5432. Find the security
group RDS created for the instance, then add one inbound rule for your IP.

```bash
export DB_SG=$(aws rds describe-db-instances --db-instance-identifier $PREFIX-db \
  --query 'DBInstances[0].VpcSecurityGroups[0].VpcSecurityGroupId' --output text --region $AWS_REGION)
export MY_IP=$(curl -s https://checkip.amazonaws.com)
aws ec2 authorize-security-group-ingress --group-id $DB_SG \
  --protocol tcp --port 5432 --cidr $MY_IP/32 --region $AWS_REGION
```

Apply the schema and ingest the corpus from your laptop, pointing at RDS:

```bash
export DATABASE_URL="postgresql://ika:REPLACE_WITH_A_STRONG_PASSWORD@$DB_HOST:5432/ika"
py -3.11 -m scripts.init_db
py -3.11 -m scripts.ingest
```

## Step 3: create the IAM role App Runner will use

App Runner needs a role that lets the running container call Bedrock. The policy
is in `deploy/bedrock-iam-policy.json`.

```bash
cat > /tmp/apprunner-trust.json <<'JSON'
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Service": "tasks.apprunner.amazonaws.com" },
    "Action": "sts:AssumeRole"
  }]
}
JSON

aws iam create-role --role-name $PREFIX-bedrock-role \
  --assume-role-policy-document file:///tmp/apprunner-trust.json

aws iam put-role-policy --role-name $PREFIX-bedrock-role \
  --policy-name bedrock-invoke \
  --policy-document file://deploy/bedrock-iam-policy.json
```

The policy allows `bedrock:InvokeModel` on any model, which is simple to start
with. To tighten it, replace the resource with the ARNs of only the Titan and
Claude models and inference profiles you use.

## Step 4: connect App Runner to the database privately

App Runner reaches RDS through a VPC connector so the traffic stays inside your
VPC. Create a security group for the connector, allow it to reach the database,
and create the connector in the same subnets as RDS.

```bash
export VPC_ID=$(aws rds describe-db-instances --db-instance-identifier $PREFIX-db \
  --query 'DBInstances[0].DBSubnetGroup.VpcId' --output text --region $AWS_REGION)
export SUBNETS=$(aws rds describe-db-instances --db-instance-identifier $PREFIX-db \
  --query 'DBInstances[0].DBSubnetGroup.Subnets[].SubnetIdentifier' --output text --region $AWS_REGION)

export CONN_SG=$(aws ec2 create-security-group --group-name $PREFIX-apprunner-sg \
  --description "App Runner VPC connector" --vpc-id $VPC_ID \
  --query GroupId --output text --region $AWS_REGION)

# Let the connector security group reach the database on 5432.
aws ec2 authorize-security-group-ingress --group-id $DB_SG \
  --protocol tcp --port 5432 --source-group $CONN_SG --region $AWS_REGION

aws apprunner create-vpc-connector \
  --vpc-connector-name $PREFIX-conn \
  --subnets $SUBNETS \
  --security-groups $CONN_SG \
  --region $AWS_REGION
export CONN_ARN=$(aws apprunner list-vpc-connectors --region $AWS_REGION \
  --query "VpcConnectors[?VpcConnectorName=='$PREFIX-conn'].VpcConnectorArn | [0]" --output text)
```

## Step 5: create the App Runner service

Put the runtime configuration in a file so the command stays readable. Replace
the password and, if needed, the Claude model id.

```bash
cat > /tmp/apprunner.json <<JSON
{
  "ServiceName": "$PREFIX-api",
  "SourceConfiguration": {
    "AuthenticationConfiguration": { "AccessRoleArn": "arn:aws:iam::$ACCOUNT_ID:role/service-role/AppRunnerECRAccessRole" },
    "AutoDeploymentsEnabled": false,
    "ImageRepository": {
      "ImageIdentifier": "$ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PREFIX-api:latest",
      "ImageRepositoryType": "ECR",
      "ImageConfiguration": {
        "Port": "8080",
        "RuntimeEnvironmentVariables": {
          "AWS_REGION": "$AWS_REGION",
          "JSON_LOGS": "true",
          "DATABASE_URL": "postgresql://ika:REPLACE_WITH_A_STRONG_PASSWORD@$DB_HOST:5432/ika",
          "BEDROCK_LLM_MODEL_ID": "us.anthropic.claude-sonnet-4-5-20250929-v1:0"
        }
      }
    }
  },
  "InstanceConfiguration": {
    "Cpu": "1024",
    "Memory": "2048",
    "InstanceRoleArn": "arn:aws:iam::$ACCOUNT_ID:role/$PREFIX-bedrock-role"
  },
  "NetworkConfiguration": {
    "EgressConfiguration": { "EgressType": "VPC", "VpcConnectorArn": "$CONN_ARN" }
  },
  "HealthCheckConfiguration": { "Protocol": "HTTP", "Path": "/health" }
}
JSON

aws apprunner create-service --cli-input-json file:///tmp/apprunner.json --region $AWS_REGION
```

The first time you use App Runner with ECR you also need the one time
`AppRunnerECRAccessRole`. If it does not exist yet, create it by following the
App Runner console prompt once, or create it with the managed policy
`AWSAppRunnerServicePolicyForECRAccess`.

## Step 6: smoke test

Get the service URL and ask a question.

```bash
export SVC_URL=$(aws apprunner list-services --region $AWS_REGION \
  --query "ServiceSummaryList[?ServiceName=='$PREFIX-api'].ServiceUrl | [0]" --output text)

curl -s https://$SVC_URL/health
curl -s https://$SVC_URL/query -H 'content-type: application/json' \
  -d '{"question":"How many days of annual leave do employees get?"}'
```

Then remove your laptop IP rule from the database, since ingestion is done:

```bash
aws ec2 revoke-security-group-ingress --group-id $DB_SG \
  --protocol tcp --port 5432 --cidr $MY_IP/32 --region $AWS_REGION
```

## Teardown

Do this when you are finished. It removes everything that costs money. Run the
steps in order.

```bash
# 1. Delete the App Runner service.
export SVC_ARN=$(aws apprunner list-services --region $AWS_REGION \
  --query "ServiceSummaryList[?ServiceName=='$PREFIX-api'].ServiceArn | [0]" --output text)
aws apprunner delete-service --service-arn $SVC_ARN --region $AWS_REGION

# 2. Delete the VPC connector (wait for the service to finish deleting first).
aws apprunner delete-vpc-connector --vpc-connector-arn $CONN_ARN --region $AWS_REGION

# 3. Delete the database. This deletes the data.
aws rds delete-db-instance --db-instance-identifier $PREFIX-db \
  --skip-final-snapshot --delete-automated-backups --region $AWS_REGION
aws rds wait db-instance-deleted --db-instance-identifier $PREFIX-db --region $AWS_REGION

# 4. Delete the security group for the connector.
aws ec2 delete-security-group --group-id $CONN_SG --region $AWS_REGION

# 5. Delete the IAM role.
aws iam delete-role-policy --role-name $PREFIX-bedrock-role --policy-name bedrock-invoke
aws iam delete-role --role-name $PREFIX-bedrock-role

# 6. Delete the ECR repository and its images.
aws ecr delete-repository --repository-name $PREFIX-api --force --region $AWS_REGION
```

Confirm nothing is left by checking that the App Runner service, the RDS
instance, and the ECR repository no longer appear in the console for this region.

## A cheaper alternative

If you want the lowest possible cost and do not need managed services, run the
whole stack on one small EC2 instance with `docker compose`: the API container
plus a pgvector container, behind the instance security group. A `t4g.small`
costs a few USD per month if you stop it when idle. The tradeoff is that you
manage the host yourself. The App Runner and RDS path above is closer to how a
real internal service is run.
